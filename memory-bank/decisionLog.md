# Decision Log

| Date | Decision | Rationale |
|------|----------|-----------|
| 2026-01-11 | Adopted XTTS-v2 (via Replicate) as the primary Voice Engine. | The previously used Minimax API was unavailable/unreliable, and Bark was too slow for real-time interaction. XTTS-v2 offers a good balance of quality and latency, supported by local reference audio injection. |
| 2026-01-11 | Renamed application entry point from DeepAgents.py to orchestrator.py. | The file name 'DeepAgents.py' collided with the installed middleware package 'deepagents', causing circular import errors and namespace confusion. |
| 2026-01-11 | Standardized on OpenTelemetry (OTLP) for Observability. | To ensure consistent tracing across LangSmith and other tools, we enabled OTLP (LANGSMITH_OTEL_ENABLED=true) targeting localhost:4318, providing a vendor-neutral observability path. |
| 2026-01-11 | Enforced MemoriPilot Protocol for Copilot Context. | To solve the issue of Copilot losing context between turns/sessions, we established the Memory Bank (MemoriPilot) as the mandatory 'long-term memory' that must be read/updated every session. |
| 2026-01-11 | Implemented Ontology-Driven Architecture (2026-01-05). | To ensure consistent agent behavior, we moved from pure prompt engineering to JSON-based Ontologies that define concepts and scoring rules. This allows programmatically checking agent outputs against a 'truth' definition. |
| 2026-01-11 | Established Reinforcement Feedback Loop (2026-01-05). | Commercial Agents now use a `bad_examples.md` file. The Confidence Agent rejects poor outputs (Score < 7) and appends them to this file, which is then fed back into the Research Agent's context to prevent repeat mistakes. |
| 2026-01-11 | Standardized Code Quality via Strict Pylinting (2026-01-08). | To ensure maintainability, we enforced a strict 10/10 Pylint standard across all core modules (`agent_brain`, `Copilot`, `model_registry`). |
| 2026-01-11 | Merged Copilot_Ontology.md into .github/copilot-instructions.md. | To consolidate the system's 'Constitution', we merged the Ontology Canon into the primary instructions file. This ensures that every session initialization loads both the MemoriPilot protocol and the architectural/behavioral ontology. |
| 2026-01-11 | Migrate from Replicate-centric to Google Vertex AI-centric Architecture | To address cost concerns and leverage higher-tier models for complex reasoning. Identified that standard Vertex AI models (Gemini-3-Pro-Preview, Lyria) have restrictive 2 RPM quotas suitable only for testing, not production. Selected 'Gemini 2.0 Flash' and 'Imagen 4 Fast' as the 'Winning Stack' to bypass these limits while providing SOTA speed and quality. Replicate serves as a necessary fallback for Audio/Video due to Google's strict quota blocks on those modalities. |
| 2026-01-11 | Disable 'deepagents' Middleware (v0.3.1) in favor of Native LangGraph | The 'deepagents' middleware library (v0.3.1) generated Pydantic validation errors ('Input should be a valid dictionary') when wrapping modern Gemini objects. Disabling the middleware and reverting to `langgraph.prebuilt.create_react_agent` eliminated these errors and restored system stability, while preserving the ability to bind tools natively. |
| 2026-01-11 | Adopt ChatGoogleGenerativeAI over ChatVertexAI | ChatVertexAI is legacy/foundational and lacks seamless support for some modern functional calling patterns required by LangGraph's tool binding. Moving to ChatGoogleGenerativeAI (via `langchain-google-genai`) ensures compatibility with the latest Vertex AI features and follows current LangChain best practices. |
| 2026-01-11 | Confirmed System Health but Identified Critical Quota Outage. | Multiple verification runs confirmed that the Agent Factory, Database Connections, and Middleware are functional. However, a hard '429 RESOURCE_EXHAUSTED' error persists across all accessible Gemini models (Flash, Pro, Lite) in the current Google Cloud Project context. This confirms the code is correct but the API usage limits have been hit. We will pause active development requiring LLM inference until quotas reset. |
| 2026-01-11 | Switching Intelligence Provider from Google to Anthropic/OpenAI (Due to Quota Friction). | The user is frustrated with Google Cloud's convoluted quota system and hard '429' blocks despite having credits. They are willing to incur cost for reliability and ease of use. Anthropic (Claude) and OpenAI (GPT-4o) are premier choices with native LangChain/LangSmith support. We will pivot the entire architecture away from the Google-specific 'Vertex AI' implementation to a standard 'ChatAnthropic' or 'ChatOpenAI' path to unlock progress. |
| 2026-01-11 | Enforce 'No-Failover' Policy for Prompts and Providers. | System must crash rather than using dummy agents or local prompt fallbacks to ensure epistemological integrity. Defaulting Intelligence to Anthropic and Media to Replicate aligns with best-in-class capabilities. |
| 2026-01-11 | Adopt Native LangSmith SDK 'workspace_id' Injection for Organization Keys. | Relying on `os.environ["LANGSMITH_WORKSPACE_ID"]` proved unreliable in the complex `ignite_atlas` runtime due to inconsistent variable persistence/import timing. We now pass `workspace_id` explicitly to the `Client()` constructor, ensuring that Organization-Scoped API Keys always have the required authorization context, preventing 400/403 errors. |
| 2026-01-12 | Switched Composer Agent to Direct Tool Execution (No Recursion). | The Composer Agent's `compose_tool` was calling `create_composer_agent` recursively, leading to infinite loops and crashes. We replaced this with `generate_music_tool` which directly calls the `minimax/music-01` (or fallback) API. This simplifies the graph and ensures reliable execution. |
| 2026-01-12 | Upgraded Composer Agent to Minimax Music-1.5. | To resolve persistent "audio format not supported" errors caused by Minimax Music-01 rejecting Lyria-generated WAV files (and lacking local FFmpeg for conversion), we switched to Minimax Music-1.5. This model generates full songs (music + vocals) from text prompts without requiring pre-generated instrumental tracks or strict file format dependencies, simplifying the pipeline and removing the failure point. |
| 2026-01-12 | Migrated Persistence to `psycopg` (v3) Binary. | The adoption of `AsyncPostgresSaver` in `DeepAgents/persistence.py` necessitated a move from `psycopg2` (v2) to `psycopg` (v3). On Windows, this required explicitly installing `psycopg-binary` and configuring the `asyncio` event loop policy to prevent `ImportError: libpq` and `NotImplementedError` crashes. |
| 2026-01-12 | Standardized Evaluation Retries with `tenacity`. | To handle API rate limits robustly during evaluation, we replaced hardcoded `time.sleep()` with `tenacity`'s exponential backoff decorators. This improves test reliability and adheres to best practices. |
| 2026-01-12 | Suppressed Pylint Import Errors via `.pylintrc`. | Due to the complex local module structure and VS Code environment, `import-error` warnings were creating excessive noise. We created a `.pylintrc` to globally disable this specific check, allowing us to focus on logic and syntax errors. |
| 2026-01-12 | Implemented Reflexion Loop for Composer Agent Logic. | To resolve user concerns about 'brittle' truncation hacks, we replaced the simple lyric truncation with a robust **Reflexion Loop**. The Composer Agent now iteratively validates generated lyrics against the Minimax Music-1.5 API schema (10-600 characters). If constraints are violated, it feeds the error back to the LLM for a rewrite (up to 3 attempts) before falling back to truncation, ensuring the system 'manipulates the model' to adhere to specs rather than just modifying the output. |
| 2026-01-12 | Enshrined Minimax Schema in System Prompt (Dynamic Prompting). | To eliminate the need for retries and truncation, we moved the Minimax Music-1.5 schema rules (Verse/Chorus/Bridge/Outro budgets) directly into the Composer's prompt. We also added a 'Transparency Patch' that forces the final output to display the *actual* lyrics sent to the API, preventing the Agent from hallucinating a longer version than what was generated. |
